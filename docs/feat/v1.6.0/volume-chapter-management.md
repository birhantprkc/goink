# 卷与章节一体化管理

> 本文档描述 v1.6.0 在已有稳定章节 ID 与分卷数据模型之上，新增的用户可见结构管理能力；不描述具体代码实现。

## 目标

将卷管理与章节管理放在同一个独立的“章节管理”Tab 中。卷是章节的分组和阅读顺序的一部分，用户应能在同一界面完成建卷、调卷、建章、插章、移动和删除章节；不再拆成两个入口或两个 Tab。

现有 SidePanel 的 `ChapterList` 保持为写作时的快速切章入口，不承担结构管理职责。

## 前提与边界

- 章节以稳定 `chapter_id` 作为引用，界面仅展示实时计算的 `reading_number`。
- 卷顺序和卷内章节顺序共同决定阅读顺序；未分卷章节始终排在最后。
- 卷和章节的结构操作仅由前端经 App API 发起；AI 不提供卷 CRUD、插章、移动或删除章节工具。
- AI 仍可借助 `chapters/new.md` 新建正文，且可读写已有卷纲；这与前端的结构管理通道独立。
- 删除章节前必须检查 timeline、story arc、reader perspective、character relation 的章节引用；writing log 保留历史孤儿引用，不阻塞删除。

## 单一 Tab 布局

“章节管理”作为 ActivityBar 的一个独立主区域。主区域由相互联动的两部分组成，而非嵌套的卷/章节子 Tab：

1. 顶部卷轨道：按阅读顺序展示卷标签，提供新建、重命名、删除和拖拽排序。
2. 下方章节列表：按卷分组展示章节，末尾固定显示“未分卷”组；每行显示实时章节号、标题、字数和操作菜单。

选择、重排或删除卷会立即反映在下方分组和章节号中。章节拖到卷标签或“未分卷”组时，移动到对应分组末尾。

## 卷操作

- 新建卷：创建空卷并追加到最后。
- 重命名：同一小说内卷名必须唯一。
- 删除卷：仅当卷内没有章节时允许；有章节时提示用户先移动或删除章节。
- 排序：拖拽卷标签进行全量重排，章节展示顺序随之更新。

## 章节操作

- 新建章节：从指定卷或“未分卷”组创建，追加到该组末尾；创建时可填写标题。
- 在前/后插入：只能插入到锚点章节所在的分组，以保证“前/后”的位置语义明确；不额外选择目标卷。
- 移动到卷：通过章节行菜单或拖拽移动到指定卷或未分卷组，追加在目标组末尾。
- 删除：先展示阻塞删除的交叉引用清单；无阻塞引用时删除正文、大纲、章节记录及对应 RAG 数据。删除后其余章节的展示编号自然连续重算。

## App API 边界

前端需要卷 CRUD 与排序 API，以及章节的新建、插入、移动、删除 API。所有章节操作均以 `chapter_id` 定位；章节新建 API 必须接受可空的目标 `volume_id`，避免“新建时可选卷”和“默认追加最后一卷”两套语义并存。

删除 API 的失败结果应能让前端展示引用类型和引用记录，而非只给出不可删除的通用提示。

## 验收标准

- 用户不离开“章节管理”Tab，即可完成卷和章节的全部结构操作。
- 卷重排、章节插入、跨卷移动和章节删除后，列表按正确阅读顺序展示连续编号。
- 交叉引用始终指向稳定章节 ID，不随展示编号变化。
- 有阻塞引用的章节不能被删除；有章节的卷不能被删除。
- 原有写作侧边栏切章、AI 新建章节及卷纲读写不受影响。
